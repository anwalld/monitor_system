# Spec Delta

## Purpose

Manager 根据每条上报给节点打 0~1 的分数，并判断节点是否因关键指标越限而剔除。分数越高越适合接任务。

## ADDED Requirements

### Requirement: 指标归一化
Manager SHALL 把每个评分指标映射到 [0, 1]：`s = clamp((坏点 − x) / (坏点 − 好点), 0, 1)`。调度延迟 P99 SHALL 先取自然对数再映射：`s = clamp((ln 坏点 − ln x) / (ln 坏点 − ln 好点), 0, 1)`，x ≤ 0 时按好点处理。输入不是有限数时 SHALL 按 0 分处理。

默认参数：CPU 忙碌度好点 0.2、坏点 0.9；调度延迟 P99 好点 100 µs、坏点 2000 µs；可用内存比例好点 0.5、坏点 0.1；网卡 RTT 好点 5 ms、坏点 100 ms，超时率好点 0、坏点 0.1，重传率好点 0、坏点 0.05。

#### Scenario: 线性映射与截断
- **WHEN** CPU 忙碌度分别为 0.1、0.2、0.55、0.9、1.0
- **THEN** CPU 分数分别为 1、1、0.5、0、0

#### Scenario: 越大越好的指标
- **WHEN** 可用内存比例为 0.3
- **THEN** 内存分数为 0.5

#### Scenario: 对数映射
- **WHEN** 调度延迟 P99 为 447.2 µs（100 与 2000 的几何平均）
- **THEN** 调度延迟分数为 0.5（误差 0.001 以内）

#### Scenario: 非有限输入
- **WHEN** CPU 忙碌度为 NaN
- **THEN** CPU 分数为 0

### Requirement: 网络分取最好的网卡
每块网卡的分数 SHALL 为 RTT、超时率、重传率三项分数的最小值；节点的网络分 SHALL 取所有网卡分数的最大值，并记下该网卡名。

#### Scenario: 一块网卡变差
- **WHEN** ens160 的 RTT 为 52.5 ms、超时率 0、重传率 0，ens192 的 RTT 为 5 ms、超时率 0.05、重传率 0
- **THEN** ens160 分数 0.5，ens192 分数 0.5；网络分 0.5

#### Scenario: 选最好的网卡
- **WHEN** ens160 分数 0.2，ens192 分数 0.9
- **THEN** 网络分 0.9，最好的网卡为 ens192

### Requirement: 加权总分与缺失项
节点总分 SHALL 为 `score = Σ wₖ·sₖ / Σ wₖ`，默认权重 CPU 0.3、调度延迟 0.3、内存 0.2、网络 0.2。样本没有调度延迟（`has_runq_p99_us()` 为 false）或 `nics` 为空时，该项 SHALL 按 `missing_score`（默认 0.3）计分，并在该节点首次出现该缺失时打一条日志提示。

#### Scenario: 全部满分
- **WHEN** CPU 0.1、调度延迟 P99 50 µs、可用内存 0.8、一块网卡 RTT 1 ms 超时与重传为 0
- **THEN** 总分为 1

#### Scenario: 老版本 Worker 没有调度延迟
- **WHEN** 其余三项都是满分，样本没有调度延迟
- **THEN** 调度延迟分数按 0.3 计，总分为 0.79；日志中有一条该节点未上报调度延迟的提示，后续样本不再重复

### Requirement: 关键指标剔除与恢复
Manager SHALL 对 CPU 忙碌度、调度延迟 P99、可用内存比例、网络（所有网卡中最小的超时率）分别判定剔除：

| 指标 | 剔除线 | 恢复线 |
|---|---|---|
| CPU 忙碌度 | ≥ 0.97 | ≤ 0.85 |
| 调度延迟 P99 | ≥ 20000 µs | ≤ 5000 µs |
| 可用内存比例 | ≤ 0.05 | ≥ 0.1 |
| 所有网卡最小超时率 | ≥ 0.5 | ≤ 0.2 |

- 连续 3 次越过剔除线 SHALL 剔除；越过剔除线 10 倍（越大越坏的指标 ≥ 10 × 剔除线，越小越坏的指标 ≤ 剔除线 / 10）SHALL 立即剔除。
- 已剔除的指标连续 5 次回到恢复线以内 SHALL 恢复；落在恢复线与剔除线之间时 MUST NOT 计为恢复，并清零恢复计数。
- 样本缺少某指标时，该指标的计数 SHALL 保持不变。
- 任一指标处于剔除状态，节点即为剔除。

#### Scenario: 连续 3 次才剔除
- **WHEN** CPU 忙碌度依次为 0.98、0.98、0.5、0.98、0.98
- **THEN** 节点始终未剔除

#### Scenario: 剔除
- **WHEN** CPU 忙碌度连续 3 次为 0.98
- **THEN** 第 3 次之后节点剔除，原因为 `cpu`

#### Scenario: 10 倍立即剔除
- **WHEN** 调度延迟 P99 一次为 250000 µs
- **THEN** 这一次之后节点立即剔除，原因为 `runq`

#### Scenario: 迟滞恢复
- **WHEN** 节点因 CPU 剔除后，CPU 依次为 0.8、0.8、0.9、0.8、0.8、0.8、0.8、0.8
- **THEN** 第 3 个值 0.9 清零恢复计数；最后一个 0.8 之后节点恢复

#### Scenario: 缺失指标不算恢复
- **WHEN** 节点因调度延迟剔除后，连续 10 条样本没有调度延迟
- **THEN** 节点仍处于剔除状态

### Requirement: 失联判定
距最近一次被接受的上报超过 `lost_after_ms`（默认 3000 ms）的节点 SHALL 视为失联，不参与选择。失联节点重新上报后 SHALL 立即回到候选集合（关键指标剔除状态保持原样）。

#### Scenario: 失联
- **WHEN** 节点最近一次上报在 3001 ms 前
- **THEN** 该节点不在候选集合中

#### Scenario: 重新上报
- **WHEN** 失联节点重新上报一条各项正常的样本
- **THEN** 该节点回到候选集合
